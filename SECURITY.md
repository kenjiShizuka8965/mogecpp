# Security policy

## Supported releases

Security fixes are applied to the current release line. At publication time, that is 0.4.x.

## Reporting a vulnerability

Please avoid filing a public issue for a vulnerability that could materially affect users before a fix is available. Contact the repository owner privately through the security-reporting mechanism enabled on the GitHub repository (for example, GitHub private vulnerability reporting) when available.

Include a minimal reproduction, affected version/commit, platform/backend, and an explanation of impact. Do not include third-party model weights or other material you do not have permission to redistribute.

## Scope

Reports concerning vendored dependencies are welcome, but upstream vulnerabilities may need to be coordinated with the corresponding upstream project. See `THIRD_PARTY_NOTICES.md` for bundled components.
